## 4. FlyDSL

- **是什么**：第三方 *Python DSL + MLIR 编译器* for AMDGPU kernels（非 aiter 一部分）。`.claude/skills/flydsl-kernel-authoring/SKILL.md`: pipeline "Python (@flyc.kernel) → AST rewriting → MLIR tracing (Fly dialect) → MlirCompiler.compile (Fly→ROCDL→LLVM→HSACO) → JITCFunction"；layout algebra（`!fly.layout`）、CopyAtom/MmaAtom/TiledCopy/TiledMma；requirements pin `flydsl==0.3.4.1`；targets gfx942/gfx950/gfx1250。`aiter/ops/flydsl/__init__.py:6-20` import `flydsl` 并 enforce `>=0.2.4`
- **aiter 如何嵌入**：kernels 以 Python 写在 `aiter/ops/flydsl/`（~100 files: `gemm_a16w16_gfx1250.py`, `fmha_gfx950/`, `moe_kernels.py`, ...）launchers 在 `aiter/ops/flydsl/kernels/`。运行期由 FlyDSL 自己的 JIT 编译；**安装期 AOT 预编译** `setup.py:414-429` 调 `aiter/aot/flydsl/common.run_aot` 进 `aiter/jit/flydsl_cache` — AOT README（`aiter/aot/flydsl/README.md`）描述 per-module "replay" drivers 在 FakeTensors 上重跑 aiter 真实 host code 以 warm 每个可达 kernel/config 组合
- **`csrc/flydsl_conv3d/`** 只含 offline tile tuner（`conv3d_tune.py` + README.md）for FlyDSL conv3d implicit-GEMM（`flydsl_conv_implicit`）；README:1-14 解释 tuned-CSV 契约与"Single backend... there is no asm/CK/triton alternative for this kernel"
- **C++ 侧 flydsl 引用只是数据布局契约**，非 codegen：`csrc/kernels/dsv4_rotate_quant.cu:140,750-753`（`Fp4ScaleLayout::Flydsl` vs `Opus` KV preshuffle）；`csrc/kernels/cache_kernels.cu:1516`（"defined in aiter/ops/flydsl/kernels/mqa_logits/pa_mqa_logits_fp4.py. The same cache..."）；`csrc/kernels/mla/metadata.cu:195,219,254`（`flydsl_ps1` plan flag, env `AITER_MLA_DECODE_PS1_FLYDSL`）

**demo potential:** partially — FlyDSL kernels 在任何有 `flydsl` wheel 的机器上独立运行（DSL 本身不需 aiter），aiter 的 tuned 表与 AOT replay 才是生产形态；`op_tests/test_flydsl_*.py`（30+ files）是现成独立 demo（需 GPU）。

## 9. Software-pipelining / layout-transformation — 三个最清晰案例

**(a) `csrc/kernels/mha_native/fused/pipeline.hpp`（527 lines）** — FMHA fwd d64，inline 文档化。Whole-kernel flow comment `:15-70`；**LDS rotation** `constexpr int LdsSeq[4] = {1,2,1,0}` `:103`（GEMM0 正在读的 K tile 停在与 GEMM1 正在写的 V tile 不同的物理 buffer）；prologue 发首个 K subtile async copy `:371-373`；tile loop `:378-430` 重叠 "prefetch K headdim half 1 while half 0 is still visible, and run GEMM0 sub-tile 0" `:388-409`，V staging 进 `LdsSeq[2]` `:430`；`sched_barrier` 调用一一镜像 CK 的 barrier 结构（codegen-parity device，explicitly "not a perf lever" `:56-64`）；bounded-buffer-SRD trick 使尾 tile OOB 读零（NaN poisoning guard）`:78-90`

**(b) `csrc/kernels/mhc_kernels.cu`** — gfx1250 TDM（tensor-DMA）ring pipeline。`MHC_TDM_KEEP(N)`/`MHC_TDM_DRAIN()` = `opus::s_wait_tensorcnt`，"KEEP1 leaves the next prefetched stage in flight (<=2 inflight, within the <=3 budget); DRAIN waits for all" `:51-65`；ring-depth/slot-reuse rationale `:229, 473`；GEMM 步间 dense `sched_barrier(0)` fences `:435,630,728,768,796,1110`；per-arch bf16 MFMA 选择带 per-arch fn-block 常量 `:34-93`（wave32 kb=16, wave64 kb=8, LDS-overflow history `:74-80`）。Companion `mega_mhc.cu` 用显式 `s_waitcnt vmcnt(0)` release points `:334,1099,1130,1249` 和 packed `v_pk_fma_f32 op_sel_hi` asm `:614-619`

## 10. `csrc/include/ck_tile/` + gemm dispatch: hipBLASLt vs CK

- `csrc/include/ck_tile/` 只有 `vec_convert.h` — shim 命名空间（`ck_tile::vec_t = thread_buffer<T,N>`, 2/4/8/16-wide fp8/fp16/bf16/f32 aliases, `:6-15`）使 aiter 侧代码可 type-match CK tile code 而无需 CK
- `csrc/include/gemm_dispatch_utils.h`: CK GEMM 目录共用的 **tuned-GEMM lookup 机制** — POD `GemmLookupKey{gfx, cu_num, M, N, K}` 常量初始化进 `.data.rel.ro` `:18-47`, `get_device_cu_num()` per-device 缓存 `:63-77`, `get_device_gfx()` key 生命周期内缓存，`GemmDispatchMap<KernelFn>`（`ck_gemm_a8w8/gemm_a8w8.cu:13` 引用）由 generated `*_lookup.h` 表按 (gfx, CU count, shape) 填充
- **hipBLASLt（"hipb"）路径不在 csrc** — 在 `gradlib/csrc/rocsolgemm.cu`（raw `hipblasLtHandle_t` `:67`, `std::map<MatMulConfig, hipblasLtMatmulHeuristicResult_t> heuristic_map` `:93`, `hipblasLtMatmul_wrapper` `:107`），经 `ROCSOLGEMM_PYBIND` 暴露 `rocb_create_extension / rocb_mm / rocb_findallsols`（`rocm_ops.hpp:1001-1005`），编译为 `hipb` extension 模块
- **后端选择是 tuned GEMM CSV 的 python `libtype` 列**: `aiter/tuned_gemm.py` `solMap = {..., "hipblaslt": hipb_gemm}` `:799`，`hipb_gemm` `:540-559` 调 `hipb_create_extension()`/`hipb_mm`；per-shape 分支 `"flydsl"` `:161`, `"opus"` `:177`, `"asm"` `:278`, `"skinny"` `:297`, fallback 默认 `hipblaslt` `:269`, gfx1250 fallback 到 `triton`/`torch` `:301-317`；dispatch funnel `solfunc = solMap[libtype]` `:448-450`。所以：CK（和 asm/opus/flydsl）服务 tuned 行；**hipBLASLt 是没 tune 时的默认**；`csrc/gemm_a16w16/README.md` 与 `mp_tuner.py` 记录 tune-vs-hipBLASLt 对比（`gemm_common.h` 只是 1 函数 `getPaddedM` extern，非后端拆分）

**demo potential:** yes — `rocb_mm` 与 CK `gemm_a8w8` 可在 plain python 里并排计时（两模块建好后），`libtype` CSV 使 "tuned-vs-hipBLASLt-fallback" 决策无需 aiter op 层即可检查。
